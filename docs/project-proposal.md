## 1. Название и организация

* **Название системы:** Веб-система согласования заявок на оплату
* **Организация / подразделение:** рекламное BTL-агентство "Мастерминд"
* **№ из таблицы примеров:** своя тема

---

## 2. Главная сущность и справочник

* **Главный объект:** заявка на оплату
* **Справочник:** контрагенты
* **Поле-ссылка:** `counterpartyId`

Одна заявка на оплату содержит ссылку на одного контрагента из справочника.

---

## 3. Роли и права

| Роль                | Создаёт | Назначает | Меняет статус |
| ------------------- | ------- | --------- | ------------- |
| Менеджер            | да      | нет       | нет           |
| Руководитель отдела | нет     | да        | нет           |
| Директор            | нет     | нет       | да            |

Руководитель отдела проверяет заявку и назначает директора отдельным действием.
Директор является назначенным исполнителем заявки и может перевести только назначенную ему заявку из `New` в `InProgress`, а после выполнения оплаты — в `Closed`.

---

## 4. Сценарий в одно предложение

Менеджер создаёт заявку на оплату, руководитель отдела проверяет её и назначает директора исполнителем, после чего назначенный директор принимает заявку в работу и подтверждает её оплату.

## 6. Что не входит в семестр

1. Реальное проведение банковского платежа.
2. Интеграция с интернет-банком или банковской системой.
3. Интеграция с 1С и бухгалтерским учётом.
4. Автоматическое формирование бухгалтерской отчётности.
5. Мобильное приложение.
6. Автоматическая отправка SMS и сообщений в мессенджеры.

---

## 7. Запас под ВКР

Возможное дальнейшее развитие системы:

1. Данные и процесс: добавить историю всех действий пользователей с заявкой: создание, проверка, назначение, отклонение, начало работы и подтверждение оплаты.
2. Данные и процесс: добавить несколько уровней согласования для заявок с большой суммой.
3. Связи с другими системами: реализовать интеграцию с 1С для передачи согласованных заявок в бухгалтерский учёт.
4. Связи с другими системами: добавить интеграцию с банковской системой для автоматической проверки факта проведения платежа.
5. Масштаб: добавить работу нескольких отделов и разграничение доступа между ними.
6. Аналитика: добавить отчёты по суммам, контрагентам, отделам и срокам согласования заявок.

---

## 8. Чем не копия соседа

Проект отличается предметной областью и главным объектом. В качестве главной сущности используется заявка на оплату, которая проходит процесс финансового согласования между менеджером, руководителем отдела и директором. Система предназначена для управления процессом согласования платежей.
