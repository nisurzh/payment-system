# Контракт API веб-системы согласования заявок на оплату

Курс: Б1.В.ДЭ.01.02.02 · КГЭУ · семестр 1 · 2026/2027 Студент: Суржиков Никита Группа: ТРИС-3-23 Дата: 18.10.2026

## 1. Назначение API

API обеспечивает взаимодействие клиентской части приложения на Vue 3 с серверной частью на ASP.NET Core.

Сервер обрабатывает запросы, проверяет данные, выполняет операции с базой PostgreSQL и возвращает результаты клиенту в формате JSON.

Базовый путь API: `/api`.

## 2. Основные эндпоинты

| Метод | Путь | Назначение | Успешный ответ |
|---|---|---|---|
| GET | `/api/payment-requests` | Получить список доступных заявок | 200 OK |
| GET | `/api/payment-requests/{id}` | Получить заявку по идентификатору | 200 OK |
| POST | `/api/payment-requests` | Создать заявку | 201 Created |
| PATCH | `/api/payment-requests/{id}/assignee` | Назначить исполнителя | 200 OK |
| PATCH | `/api/payment-requests/{id}/status` | Изменить статус заявки | 200 OK |
| GET | `/api/counterparties` | Получить список контрагентов | 200 OK |

## 3. Получение списка заявок

**Запрос:** `GET /api/payment-requests`

Назначение: получение списка заявок, доступных текущему пользователю в соответствии с его ролью и правами.

Пример ответа:

```json
[
  {
    "id": 1,
    "number": 1001,
    "title": "Оплата аренды оборудования",
    "description": "Оплата оборудования для мероприятия",
    "amount": 25000.00,
    "status": "New",
    "counterpartyId": 3,
    "createdByUserId": 2,
    "assigneeUserId": null,
    "createdAt": "2026-10-18T10:30:00Z"
  }
]
```

Возможные ответы:

- `200 OK` — список успешно получен;
- `401 Unauthorized` — пользователь не авторизован;
- `403 Forbidden` — у пользователя нет прав на выполнение запроса.

## 4. Получение заявки по идентификатору

**Запрос:** `GET /api/payment-requests/{id}`

Назначение: получение подробной информации об одной заявке.

Пример: `GET /api/payment-requests/1`.

Пример ответа:

```json
{
  "id": 1,
  "number": 1001,
  "title": "Оплата аренды оборудования",
  "description": "Оплата оборудования для мероприятия",
  "amount": 25000.00,
  "status": "New",
  "counterpartyId": 3,
  "createdByUserId": 2,
  "assigneeUserId": null,
  "createdAt": "2026-10-18T10:30:00Z"
}
```

Возможные ответы:

- `200 OK` — заявка найдена;
- `401 Unauthorized` — пользователь не авторизован;
- `403 Forbidden` — у пользователя нет прав на просмотр заявки;
- `404 Not Found` — заявка не найдена.

## 5. Создание заявки

**Запрос:** `POST /api/payment-requests`

Назначение: создание новой заявки менеджером.

Пример тела запроса:

```json
{
  "title": "Оплата аренды оборудования",
  "description": "Оплата оборудования для мероприятия",
  "amount": 25000.00,
  "counterpartyId": 3
}
```

При создании сервер проверяет обязательные поля, существование контрагента и корректность суммы. Создатель определяется по авторизованному пользователю.

Сервер самостоятельно формирует `id`, уникальный `number`, дату создания и статус `New`. Поле исполнителя первоначально не заполнено.

Пример успешного ответа:

```json
{
  "id": 1,
  "number": 1001,
  "title": "Оплата аренды оборудования",
  "description": "Оплата оборудования для мероприятия",
  "amount": 25000.00,
  "status": "New",
  "counterpartyId": 3,
  "createdByUserId": 2,
  "assigneeUserId": null,
  "createdAt": "2026-10-18T10:30:00Z"
}
```

Возможные ответы:

- `201 Created` — заявка создана;
- `400 Bad Request` — данные не прошли проверку;
- `401 Unauthorized` — пользователь не авторизован;
- `403 Forbidden` — у пользователя нет прав на создание заявки;
- `404 Not Found` — указанный контрагент не найден.

## 6. Назначение исполнителя

**Запрос:** `PATCH /api/payment-requests/{id}/assignee`

Назначение: назначение директора исполнителем заявки руководителем отдела.

Пример тела запроса:

```json
{
  "assigneeUserId": 5
}
```

Сервер проверяет существование заявки, права руководителя отдела и соответствие назначаемого пользователя роли директора.

Назначение исполнителя не изменяет статус заявки. Если заявка имела статус `New`, он остаётся `New`.

Пример успешного ответа:

```json
{
  "id": 1,
  "number": 1001,
  "status": "New",
  "assigneeUserId": 5
}
```

Возможные ответы:

- `200 OK` — исполнитель назначен;
- `400 Bad Request` — данные некорректны;
- `401 Unauthorized` — пользователь не авторизован;
- `403 Forbidden` — у пользователя нет прав на назначение;
- `404 Not Found` — заявка или исполнитель не найдены;
- `409 Conflict` — назначение невозможно из-за текущего состояния заявки.

## 7. Изменение статуса заявки

**Запрос:** `PATCH /api/payment-requests/{id}/status`

Назначение: изменение статуса заявки в соответствии с разрешёнными переходами.

Пример тела запроса:

```json
{
  "status": "InProgress"
}
```

Допустимые переходы:

| Текущий статус | Новый статус | Кто выполняет действие |
|---|---|---|
| `New` | `InProgress` | Назначенный директор |
| `InProgress` | `Closed` | Назначенный директор |
| `New` | `Cancelled` | Руководитель отдела |
| `InProgress` | `Cancelled` | Назначенный директор |

Сервер проверяет роль пользователя, назначение исполнителя и допустимость перехода между статусами.

Пример успешного ответа:

```json
{
  "id": 1,
  "number": 1001,
  "status": "InProgress",
  "assigneeUserId": 5
}
```

Возможные ответы:

- `200 OK` — статус изменён;
- `400 Bad Request` — указан неизвестный статус или некорректные данные;
- `401 Unauthorized` — пользователь не авторизован;
- `403 Forbidden` — переход недоступен пользователю;
- `404 Not Found` — заявка не найдена;
- `409 Conflict` — переход запрещён текущим статусом заявки.

## 8. Получение списка контрагентов

**Запрос:** `GET /api/counterparties`

Назначение: получение справочника контрагентов для выбора при создании заявки.

Пример ответа:

```json
[
  {
    "id": 3,
    "name": "ООО Пример"
  },
  {
    "id": 4,
    "name": "ООО Поставщик"
  }
]
```

Возможные ответы:

- `200 OK` — список получен;
- `401 Unauthorized` — пользователь не авторизован.

## 9. Общие правила API

1. Данные передаются в формате JSON.
2. Для запросов, требующих авторизации, сервер определяет пользователя по данным аутентификации.
3. Проверка ролей и прав выполняется на сервере, а не только в клиентском интерфейсе.
4. Клиент не может самостоятельно устанавливать `id`, `number` или `createdByUserId` при создании заявки.
5. Назначение исполнителя и изменение статуса являются разными операциями.
6. Удаление заявки через `DELETE` не предусмотрено. Отклонённая заявка сохраняется в базе со статусом `Cancelled`.
7. Сервер проверяет обязательные поля, существование связанных записей и допустимость операций.
8. Ошибки возвращаются с соответствующим HTTP-кодом и описанием причины.
